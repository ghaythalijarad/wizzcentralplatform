## 📊 System Architecture

### Data Flow
```
WizzCentral Frontend
    ↓ (HTTP POST)
WizzCentral Server (port 3000)
    ↓ (calls Lambda function)
merchant-info-notification.js
    ↓ (queries)
DynamoDB Tables:
  - WhizzMerchants_Businesses (get merchants)
  - WhizzMerchants_DeviceTokens (get FCM tokens)
    ↓ (sends via)
Firebase Admin SDK
    ↓ (delivers to)
WhizzMerchants App on iPhone
    ↓ (displays)
iOS Notification Banner
```

### Issue #3: Notifications Don't Appear
**Possible Causes:**
1. App in foreground (iOS won't show banner)
2. Do Not Disturb enabled
3. Notification permissions denied
4. Invalid/expired FCM token

**Solutions:**
1. Minimize app (press home button)
2. Disable Do Not Disturb
3. Check Settings > WhizzMerchants > Notifications
4. Re-register token by logging out and back in

## 🎓 Key Learnings

### Firebase Integration
- Firebase Admin SDK is more reliable than legacy FCM API
- Service account credentials provide full administrative access
- Token validation happens automatically on send

### iOS Push Notifications
- Notifications only show when app is in background/closed
- Foreground notifications require custom handling
- Device tokens can expire and need refresh handling

### DynamoDB Best Practices
- Use GSI for efficient querying by secondary keys
- Project only needed attributes to reduce cost
- Handle missing attributes gracefully
